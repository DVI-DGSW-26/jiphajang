# 받은 자료 분석

2026-10-08에 물류팀에게 받은 업무 자료(엑셀 16개, 업무 설명 그림 3장)를 분석한 결과예요. 원천자료가 어떻게 생겼고, 지금 엑셀에서 무엇을 손으로 하고 무엇을 수식으로 하는지 정리했어요.

> **실제 값은 적지 않아요.** 이 저장소는 공개라서 고객사·회사·창고·포워더 이름, 품번, 단가, 수량은 `고객사 A`, `창고 1`, `품번 P1`처럼 바꿔 적어요. 원본 파일은 저장소에 넣지 않아요.

## 1. 받은 자료

| 묶음 | 파일 | 쓰임 |
|---|---|---|
| 업무 설명 | 한국 출하 · 현지 출하 · 재고 흐름 그림 3장 | Invoice 칸이 결과 엑셀의 어느 열로 가는지, 어떤 열이 수기입력·고정값인지 표시 |
| 업무 설명 | 고정값 엑셀 | 코드 → 고객사·인도조건 조회표 (4장 참고) |
| 한국 출하 | 한국 출하 Invoice 5개 | 원천자료. 고객사에 PDF로 보내요 |
| 한국 출하 | 수출신고취합 | 결과. 내부 보고용 엑셀 |
| 현지 출하 | 현지 출하 Invoice 6개 | 원천자료. 고객사에 PDF로 보내요 |
| 현지 출하 | 현지 출하 Invoice List | 결과. 내부 보고용 엑셀 |
| 현지 출하 | 현지 창고 재고 및 선적 관리 | 결과. 재고·선적을 관리하는 작업 파일 |
| 현지 출하 | 현지 창고 재고 및 출하 현황 | 결과. 내부 보고용 엑셀 |

**빠진 것:** 범위 문서의 결과 중 **현지 수금현황**과 **U71X Offset Cost Review**는 파일이 없어요. 받은 파일 어디에도 수금·Offset·소급 계산이 없어서 따로 받아야 해요(10장 1번).

Invoice는 모두 **엑셀(.xlsx)** 로 받았어요. 고객사에는 PDF로 보내지만 원천은 엑셀이라, 판독은 엑셀을 읽는 방식으로 해요.

## 2. 전체 흐름

```
한국 공장 ──한국 출하 Invoice──▶ 수출신고취합 (한국 출하 원장)
     │                                   │
     └─ 선적 ─▶ (선적중) ─▶ 현지 창고 도착 ─┐
                                          ▼
                              현지 창고 재고 및 선적 관리 ──▶ 현지 창고 재고 및 출하 현황
                                          ▲
현지 법인 ──현지 출하 Invoice──▶ 현지 출하 Invoice List (현지 출하 원장)
```

- 한국 출하: 한국 본사가 미국 현지 법인(또는 고객사)에 수출해요. Invoice 하나 = 선적 하나(컨테이너 단위로 A/B 차수).
- 현지 출하: 현지 창고에서 고객사로 보내요. 현지 법인이 Invoice를 발행해요.
- 재고: 한국에서 도착한 수량을 더하고, 현지 출하 수량을 빼서 날마다 기말재고를 구해요.

지금은 세 흐름이 **각자 다른 엑셀에 손으로 옮겨 적혀** 있어요. 파일끼리 연결된 수식은 하나도 없어요.

## 3. 한국 출하

### 3.1 Invoice 양식

한 파일에 Invoice 시트와 Packing List 시트가 있어요. **고객사마다 양식이 달라서** 칸 위치가 서로 달라요.

| 항목 | 위치 차이 |
|---|---|
| Invoice No. & 날짜 | 모두 E4 한 칸에 `번호 & MON DD YYYY` 문자열로 |
| Shipper / Consignee / Notify | A4 / A20 / A23 (공통) |
| 인도조건 | E19 또는 E20의 Remarks 문구 안에 (`DAP`, `DDP`, `CIF`) |
| 선박 · 출항일 | A32·C32 또는 E29. 출항일이 **없는 양식**도 있어요 |
| 품목 머리줄 · 품목 행 | 31행 또는 35행부터. 한 양식은 항목 이름이 **스페인어** |
| 품목 열 | 포장 수, 단위, 품명, (HS 코드, 원산지), 수량, 단가, 금액 |
| CIF / Freight / Insurance / FOB | 한 양식에만 있어요 |
| Packing List | Net / Gross Weight, 팔레트 치수(글자). **CBM은 없어요** |

- 수량은 대부분 `Set 수량 × 팔레트 수` 수식이고, 단가·팔레트 수·품명·날짜·선박은 손으로 쳐요.
- 중량 계수(팔레트당 kg, 개당 kg)가 수식 안에 숫자로 박혀 있어요.
- **판독은 칸 좌표 대신 항목 이름으로 찾아야 해요.** 예: `Description of Goods`(또는 스페인어 표기) 아래부터 `Total` 위까지가 품목.

**같은 선적의 Invoice가 두 벌인 경우:** 파일 이름 끝에 `(83%)`, `(100%)`처럼 비율이 붙은 경우가 있어요. 삼각무역이라 같은 번호로 수출신고용(본사 → 현지 법인)과 재판매용(현지 법인 → 고객사)이 따로 있고, 수출신고취합에는 **수출신고용만** 들어가요. 비율은 단가 비율로 보이지만 지금 단가와 맞지 않아요(10장 2번).

### 3.2 Invoice 번호 규칙

```
V  C  261007  A
│  │  │       └ 선적 차수 (같은 날 컨테이너 여러 대면 A, B …)
│  │  └ 날짜 YYMMDD
│  └ B.Ship to 코드 (고객사 구분, 4장)
└ Origin (V = 한국)
```

수출신고취합의 Invoice 열이 실제로 `=Origin & B.Ship & TEXT(날짜,"yymmdd") & 차수` 수식이에요. **번호 하나에서 Origin·B.Ship·Ship date·차수가 다 나와요.** 품번과 Consignee로 B.Ship을 한 번 더 확인할 수 있어요.

### 3.3 수출신고취합

연도별 시트(`2023년` ~ `2026년`)가 원장이에요. 그 앞의 월별 시트는 옛 구조(열이 적음)이고, 숨김 시트 2개와 옛 품목 시트 2개가 함께 있어요. 피벗이나 요약 시트는 없어요.

| 열 | 머리줄 | 분류 | 비고 |
|---|---|---|---|
| A | No | 계산 | 출하 순번. Invoice 파일 이름 앞 번호와 같아요 |
| B | Origin | 판독 | 번호 1번째 글자 |
| C | B. Ship to | 판독 | 번호 2번째 글자 |
| D, E | Year, Month | 계산 | **선적일자(R) 기준** 연·월 |
| F | Ship date | 판독 | Invoice 날짜 |
| G | Shipment # | 판독 | 번호 끝 글자 |
| H | 인도조건 | 마스터 | 고정값 표. Invoice Remarks와 대조 |
| I | 필증# | 직접 입력 | 수출신고번호 |
| J | Invoice | 계산 | 3.2의 수식 |
| K, L | BL#, Container No. | 직접 입력 | |
| M~O | 고객사 / 고객사 / 회사명 | 마스터 | 고정값 표 |
| P | 출하일자 | 직접 입력 | 생산부 기준. 기본값은 Ship date |
| Q | 수리일자 | 직접 입력 | |
| R | 선적일자 | 직접 입력 | 회계부 기준 |
| S | 품명 | 판독 + 매핑 | Invoice 품명을 원장 표기로 바꿔요(3.4) |
| T | 단가 | 판독 | USD |
| U | Set QTY | 마스터 | 팔레트당 수량 |
| V | Box QTY | 판독 | **팔레트 수** |
| W | Total QTY | 계산 | `U × V` |
| X | 금액(USD) | 계산 | `T × W`. Invoice 금액과 같아요 |
| Y | 환율 | 직접 입력 | |
| Z | 금액(KRW) | 계산 | `X × Y` |
| AA | 확정마감 금액(KRW) | 직접 입력 | 회계 마감값. Z와 몇 원 차이 |
| AB | 도착일 | ? | 실제로는 메모로 쓰여요 |
| AC~AG | ETD, ETA, ATA_PORT, AV.DATE, AVG | 직접 입력 | 최근 3년 모두 비어 있어요 |

### 3.4 Invoice → 원장으로 옮길 때 바꾸는 것

- **품명:** Invoice의 긴 품명(재질·열처리 번호 포함)을 원장의 짧은 표기로 바꿔요. 품목마다 별칭이 필요해요.
- **포장 수:** 한 양식은 카톤 수를 적지만 원장은 팔레트 수를 써요. 팔레트당 카톤 수가 필요해요.
- **단가:** 한 양식은 화면에 보이는 단가가 없어서 `총액 ÷ 수량`으로 구해야 해요. 이 양식의 총액에는 Freight·Insurance가 들어 있어요(10장 5번).

## 4. 고정값(코드) 표

| 코드 | 값 | 쓰는 곳 |
|---|---|---|
| Origin + B.Ship (`V`+`C`/`R`/`E`/`M`) | 인도조건(DAP/DDP/CIF), 고객사, 회사명 | 수출신고취합 |
| Plant + P/C (`M`+`C`/`T`, `R`+`1`~`4`) | Ship to, 제품코드 | 현지 출하 Invoice List |

- 받은 고정값 엑셀은 **두 표의 제목이 서로 바뀌어** 있어요(10장 6번).
- 원장을 보면 코드 뜻이 해마다 달라졌어요(예: 어떤 코드의 인도조건이 DDP → DAP). 이 4개 말고 옛 코드도 있어요. **코드표에 적용 기간이 필요해요.**

## 5. 현지 출하

### 5.1 Invoice 양식

시트는 Invoice / Packing Slip / Item Data / Address Data 넷이에요. 고객사에 따라 세 가지 모양이 있어요.

| 항목 | 위치 |
|---|---|
| Bill To | A7~A10 (한 양식은 Address Data에서 조회) |
| Invoice Date / No. / Ship Date | F6 / F7 / F8 (`=F6`) |
| P/O No. / Term / Due Date | F9 / F10 / F11 (`Ship Date + 일수`) |
| Ship Via 또는 Incoterm | F12 (양식마다 다름) |
| 품목 | 13~14행부터. **열 순서가 양식마다 달라요** (QTY·BOX QTY vs Set QTY·BOX QTY·QTY) |
| TOTAL | 24~27행 `SUM` |
| Remit To | 고객사에 따라 **현지 법인 또는 한국 본사** 계좌 |

- 수량은 `Set 수량 × Box 수` 수식이고, Set 수량이 수식에 숫자로 박혀 있거나 Item Data에서 조회해요.
- 파일 이름 끝의 꼬리 번호(`-0XX` 등)는 품번 끝자리예요. Invoice 번호에는 들어가지 않아요.

### 5.2 Invoice 번호 규칙

- `M` 계열: `Plant + P/C + YYMMDD + 순번` (예: `MT261007A`). 앞 두 글자가 제품코드예요.
- `R` 계열: `R + P/C + MMDD + 고객 글자 + Ship From 코드` (예: `R11007BSC`).

### 5.3 현지 출하 Invoice List

연도별 시트(`MASTER_2022` ~ `MASTER_2026`)가 원장이에요. 2024년부터 지금 구조예요. 같은 파일에 **현지 출하가 아닌 시트**(일본 수출 실적, 다른 고객사 수출)와 품목·주소 조회 시트가 섞여 있어요.

| 열 | 머리줄 | 분류 | 비고 |
|---|---|---|---|
| A | No. | 계산 | 순번. 중복 있음 |
| B, C | Plant, P/C | 판독 | Invoice 번호 앞 두 글자 |
| D | 제품코드 | 계산 | `B & C` |
| E | Invoice date | 판독 | |
| F~H | Invoice MM / DD / YY | 계산 | E에서 나눠요 |
| I | Ship to | 마스터 | 코드표 |
| J | Ship From | 마스터 | 코드 뜻이 정의돼 있지 않아요 |
| K | Invoice # | 판독 | |
| L | Part Number | 판독 + 매핑 | 원장 표기와 Invoice 표기가 달라요 |
| M | Unit Price | 판독 | |
| N | Set QTY | 마스터 | |
| O | Box QTY | 판독 | |
| P | Total QTY | 계산 | `N × O` |
| Q | Total Amount | 계산 | `M × P` |
| R | Original Amount | 계산 | Invoice 한 건(여러 줄)의 합계. 한 고객사만 |
| S | Discount Amount | 계산 | `R − T`. 이름과 달리 **할인 뒤 금액** |
| T | Discount Charges | 직접 입력 | 할인액. 2~3개월 늦게 들어와요. 조기 지급 할인으로 보여요 |
| U | CARRIER | 판독 | Ship Via |
| V | Tracking# | 직접 입력 | |
| W | Due Date | 계산 | 지금은 비어 있음. 예전에는 `Invoice date + 결제 일수` 수식 |
| X~Z | ASN / Inbound Date / Fiscal Date | ? | 비어 있음 |

**수금과 관련된 것은 R·S·T(할인)뿐**이고, 수금일·미수 열은 쓰이지 않아요. 수금현황은 다른 파일에서 관리하는 것으로 보여요.

## 6. 현지 창고 재고

### 6.1 재고 및 선적 관리 (작업 파일)

고객사·모델별 시트(보이는 시트 3개, 숨김 1개)에 **품번 하나당 7줄짜리 묶음**이 있고, 오른쪽으로 **하루에 한 열**씩 몇 년치 날짜가 이어져요.

| 줄 | 입력 | 내용 |
|---|---|---|
| 국내출하 | 직접 | 거의 안 써요 |
| 기초재고 | 수식 | `= 전날 기말재고` |
| 실적입고 | — | 비어 있어요 |
| 현지출하 | 직접 | 현지 Invoice 수량. **앞으로 나갈 예정 수량도 같은 줄에** 적어요 |
| 기말재고 | 수식 | `기초 + 실적입고 + 창고도착 − 현지출하`. 실사 뒤에는 **값으로 덮어써요** |
| 실사재고 | 직접 | 가끔 |
| 창고도착 | 직접 | 한국 선적분 도착 수량. **도착 예정분도 미리** 적어요 |

- 창고도착 아래 줄에 Invoice 번호와 포워더를 메모로 적어요.
- 날짜 머리줄 위에 `날짜 − 리드타임` 줄이 있어서, 그날 도착하려면 한국에서 언제 실어야 하는지 보여줘요. 리드타임은 고객사마다 30~45일.
- **선적중(In Transit) 줄은 없어요.** 선적중 수량은 메모로만 남아요.
- 그 밖에 선적 계획, 팔레트·중량 계산, 지난 양식(선적 스케줄: 포워더·서류마감·ETD·ETA·Booking·BL·Container·선사·선박) 시트가 있어요.

### 6.2 재고 및 출하 현황 (보고서)

한 시트에 세 구역이 있어요. **모든 값을 작업 파일에서 손으로 옮겨** 적고, 기준일도 글자로 적어요.

| 구역 | 내용 |
|---|---|
| 고객사별 재고보고 | 창고 → 고객사 → 품번. 일소요량, 현지창고 재고, **선적중 재고(Invoice별 열)**, 단가, 재고금액 |
| 현지 출하현황 | 품번 × 날짜, 출하 수량 |
| 현지 재고현황 | 품번 × 날짜, 그날 기말재고 |

- 재고금액 = `(현지창고 재고 + 선적중 재고) × 단가`.
- 선적중 재고 = 한국에서 실었지만 기준일까지 도착하지 않은 Invoice 수량.

### 6.3 앱에서 구하는 식 (품번 p, 창고 w, 날짜 d)

| 값 | 식 |
|---|---|
| 현지재고(d) | 기초 + Σ도착(도착일 ≤ d) − Σ현지출하(출하일 ≤ d) + Σ실사 조정(≤ d) |
| 선적중(d) | Σ한국 선적 수량 (선적일 ≤ d, 도착 안 했거나 도착일 > d). Invoice별로 펼쳐요 |
| 재고금액(d) | (현지재고 + 선적중) × d 시점 단가 |
| 출하현황 · 재고현황 | 위 값을 날짜별로 |
| 예상 재고 | 현지재고 + 도착 예정 − 출하 예정. **실적과 따로 보여줘요** |
| 선적 필요일 | 필요일 − 리드타임 |

## 7. 마스터로 뽑을 것

| 마스터 | 내용 | 지금 있는 곳 |
|---|---|---|
| 고객사 | 이름, 코드(B.Ship / Plant), 회사명, 결제조건, 송금 법인, 리드타임 | 고정값 표, 주소 시트, Invoice |
| 코드표 | Origin·B.Ship·Plant·P/C → 인도조건·고객사·Ship to. **적용 기간 포함** | 고정값 표 |
| 품번 | 고객사, 모델, 원장 표기, **Invoice 표기 별칭**, Set QTY, 팔레트당 카톤 수, 중량 계수 | 원장, Invoice 수식, 옛 품목 시트 |
| 단가 | 품번, 단가(USD), 적용 시작일. 한국 출하용과 현지 출하용이 달라요 | 원장·Invoice 메모 |
| 창고 | 이름, 지역, 고객사 | 재고 보고서 |
| 포워더 | 코드, 이름 | 메모 |

옛 품목 시트들은 지금 품번이 빠져 있거나 단가가 옛날 값이에요. **지금 단가·Set QTY의 기준은 원장과 Invoice뿐**이에요.

## 9. 이관할 때 손봐야 할 원천 데이터

| 문제 | 어디 | 처리 |
|---|---|---|
| 날짜가 글자로 저장됨(앞 공백·탭) | 수출신고취합 | 이관 때 날짜로 바꿔요 |
| 번호 형식이 섞임(하이픈 유무, 끝 공백·`/`) | 필증#, BL#, Container No. | 정규화 규칙 필요 |
| Invoice 번호 오타(자릿수) | 재고 메모 | 확인 목록으로 뽑아요 |
| 연·월이 선적일과 안 맞는 행 | 수출신고취합 연초 | Year·Month는 계산값으로 다시 구해요 |
| 확정마감 금액을 지난달에서 복사 | 수출신고취합 최근 행 | 이관 대상에서 빼고 확인 |
| 다른 통화(엔화) 행이 USD 열에 섞임 | 수출신고취합 | 범위 확인(10장 3번) |
| 합계 범위가 마지막 행을 빠뜨림 | Invoice List, 재고 보고서 | 앱에서는 합계를 다시 구해요 |
| 연도 열에 다른 해 날짜가 박힘 | Invoice List | 계산값으로 다시 구해요 |
| 기말재고를 값으로 덮어씀 | 재고 작업 파일 | 차이를 실사 조정 기록으로 바꿔요 |
| 품번 표시가 다른 묶음을 가리킴, `#REF!` | 재고 작업 파일 | 품번은 묶음 위치로 다시 읽어요 |
| 같은 품번 단가가 파일마다 다름 | 재고 작업 파일 · 보고서 · 원장 | 단가 마스터를 적용 기간으로 정리 |
| 닫힌 외부 링크 수천 개 | 세 파일 모두 | 무시해요. 실제로 쓰는 참조는 거의 없어요 |
| 음수 재고 | 쓰지 않는 품번 | 이관 범위에서 빼는지 확인 |

## 10. 물류팀에 확인할 것

1. **현지 수금현황과 U71X Offset Cost Review** 원본 파일과 계산 기준(Offset Cost, 소급 정산)을 받을 수 있나요?
2. 한국 Invoice 파일 이름의 비율(`74%`, `83%`, `100%`)은 무엇의 비율인가요? 재판매용 Invoice(100%)도 시스템에 보관해야 하나요?
3. 일본 수출, 범위 문서에 없는 고객사(숨김 시트·다른 시트에 있는 건)도 이번 범위에 들어가나요? 다른 통화 건은 어떻게 하나요?
4. 수출신고취합의 Year·Month 기준은 선적일자가 맞나요? 확정마감 금액은 누가, 언제 넣나요? 도착일·ETD·ETA 열은 앞으로 쓰나요?
5. Freight·Insurance가 들어간 Invoice의 원장 금액은 총액이 맞나요? Steel / Non-steel을 나누는 기준은 무엇인가요?
6. 고정값 엑셀의 두 표 제목(한국출하·현지출하)이 서로 바뀐 게 맞나요? 이 4개 말고 옛 코드도 지원해야 하나요?
7. 창고 도착은 어느 날짜 기준인가요? (ETA / 실제 도착 / 창고 입고 확인) 실적입고 줄을 쓰지 않는 이유는 무엇인가요?
8. 실사 차이는 누가 승인하고 어떻게 처리하나요?
9. 재고금액에 쓰는 단가는 판가인가요, 원가인가요? 어느 날짜의 단가를 쓰나요?
10. 일소요량과 앞으로의 출하 예정 수량은 어디서 받나요? (PO, 고객 예측)
11. 결제조건이 Invoice·주소 시트·납기 계산식마다 다른 고객사가 있어요. 어느 것이 맞나요?
12. 할인(Discount Charges)이 한 고객사에만 있는 이유와 할인율 기준은 무엇인가요?
13. Ship From 코드(`A`, `SC` 등)의 뜻은 무엇인가요?
14. 품번 표기의 괄호 안 숫자(예: `P1(822)`)는 무엇인가요?
15. 팔레트당 카톤 수, 중량 계수, CBM을 마스터로 관리해도 되나요?
16. 한 고객사의 한 모델 품목이 창고 두 곳에 나뉘어 있어요. 창고를 옮긴 날짜는 언제인가요?
