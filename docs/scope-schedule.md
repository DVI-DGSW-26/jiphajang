# 개발 범위와 일정 — 개발용 요약

원본: [`scope-schedule.pdf`](scope-schedule.pdf) (2026-08-27). 값이 서로 다르면 PDF가 기준이에요.
일정은 착수일 기준 **N주차**로 적어요. 착수일이 정해지면 실제 날짜로 바꿔요.

## 1. 전체 흐름

파일을 따로따로 관리하지 않고, **원천자료 → 출하 원장 → 조회·집계 결과**로 이어지는 한 시스템으로 만들어요.

1. 원천자료(Invoice) 등록·판독
2. 마스터와 출하 원장 관리
3. 수출신고·Invoice List·수금·Offset 자동 산출
4. 재고·선적 정보 관리
5. 기존 데이터 이관과 통합 검증

## 2. 개발 대상

| 구분 | 대상 | 수량 |
|---|---|---|
| 원천자료 | 한국 출하 Invoice | 5 |
| 원천자료 | 현지 출하 Invoice (공통 양식·참조 데이터 포함) | 6 |
| 결과 | 수출신고취합 | 1 |
| 결과 | 현지 출하 Invoice List | 1 |
| 결과 | 현지 수금현황 | 1 |
| 결과 | U71X Offset Cost Review | 1 |
| 결과 | 현지 창고 재고 및 선적 관리 | 1 |
| 결과 | 현지 창고 재고 및 출하 현황 | 1 |

- 현지 Invoice 수량은 남은 고객사 샘플을 받은 뒤 확정해요. 양식이 늘면 판독 개발 기간도 늘어요.
- 현지 출하 Invoice List는 입력 화면이 아니에요. **출하 원장을 조회·집계하는 결과 화면**이에요.

## 3. 시스템 구성

| 구분 | 내용 |
|---|---|
| 마스터 + 출하 원장 | 품번·단가·주소·결제조건 등 마스터, 통합 출하 원장 |
| 파생 결과 | 수출신고취합, 현지 Invoice List, 수금현황, U71X Offset 자동 산출 |
| 재고·선적 관리 | 입고·출고·선적·In Transit 트랜잭션 |
| 데이터 이관 | 기존 데이터를 정리·변환해 새 시스템으로 옮김 |

## 4. 데이터 처리 원칙 (잠정)

| 원천 데이터 | 처리 | 화면 표시 ([디자인 매뉴얼](design-manual.md) 원칙 2) |
|---|---|---|
| 원천자료에 있음 | 시스템 자동 입력 | 자동 칸 |
| 계산할 수 있음 | 시스템 자동 산출 | 자동 칸 |
| 원천자료에 없음 | 담당자 직접 입력 | 직접 입력 칸 |

직접 입력 예: 수출신고번호, BL No., Container No., 실제 수금일, ETD / ETA / ATA, 선박 정보, 포워더 정보.
항목별 처리 방식은 착수 후 물류팀과 협의해 확정해요.

## 5. 주차별 일정 (총 15주)

| 주차 | 단계 | 주요 작업 | 결과물 |
|---|---|---|---|
| 1 | 착수 | 범위·일정 확인, 선행자료 목록·제출 일정·담당자 협의 시작 | 착수보고서, 대상 목록, 자료 제출 계획(안) |
| 2 | 분석 | Invoice 양식별 판독 규칙, 마스터 검증, 이관 샘플 검토, 자료 제출 일정·담당자 확정 | 판독 정의서, 마스터 검토 결과, 자료 제출 계획 확정본 |
| 3 | 설계 | 출하 원장 구조, 항목 매핑, 산출 로직 확정 | 원장 정의서, 매핑표, 산출 로직 정의서 |
| 4 | 개발 | 마스터·출하 원장 | 마스터·원장 기능 |
| 5 | 개발 | 한국 Invoice 5종 + 현지 공통 양식 판독·연계 | Invoice 판독 기능 |
| 6 | 개발 | 현지 남은 고객사 Invoice 양식 판독 | 추가 Invoice 판독 기능 |
| 7 | 개발 | 수출신고취합 | 수출신고취합 기능 |
| 8 | 개발 | 현지 출하 Invoice List | Invoice List |
| 9 | 중간검증 | 원장·기본정보·1차 결과 검증과 보완 | 중간 검증 결과 |
| 10 | 개발 | 현지 수금현황, U71X Offset | 수금·Offset 기능 |
| 11 | 설계·개발 | 재고·선적 구조 설계, 기본 기능 | 재고·선적 모델 |
| 12 | 개발 | 재고·선적 관리, 재고·출하 현황 | 재고·선적 기능 |
| 13 | 데이터 이관 | 정리 → 변환 → 검증 → 이관 | 이관 결과 |
| 14 | 통합 테스트 | 전체 기능·데이터 연계 | 테스트 결과 |
| 15 | 최종검증 | 사용자 검증, 보완, 운영 적용 | 최종 검증 결과, 운영 적용 |

물류팀 참여 시점: **1주차**(자료 협의 시작), **2주차**(제출 일정·담당자 확정, 판독 규칙·마스터 기준 확인), **9주차**(중간 검증), **13주차**(이관 결과 확인), **15주차**(최종 사용자 검증).

## 6. 선행자료 (모두 1~2주차에 제출 일정 협의)

| 구분 | 자료 | 담당 |
|---|---|---|
| Invoice 양식 | 한국 출하 Invoice 5종 | 물류팀 |
| Invoice 양식 | 현지 출하 Invoice 남은 고객사 샘플 | 물류팀 |
| 판독 기준 | Invoice에서 읽을 항목과 위치 | 물류팀 |
| 마스터 | 품번·품명·고객사·Plant·주소·결제조건 | 물류팀 |
| 마스터 | 단가 유형과 적용기간 기준 | 물류팀 |
| 산출 기준 | 금액·환율 계산 기준 | 물류팀 |
| 산출 기준 | 수금계획일·미수 계산 기준 | 물류팀 |
| 산출 기준 | Offset Cost 계산·소급 정산 기준 | 물류팀 |
| 입력 기준 | 자동입력·자동산출·직접입력 항목 구분 | 공동 |
| 이관 | 이관 대상 기간과 범위 | 물류팀 |
| 이관 | 기존 데이터 오류·불일치 처리 기준 | 물류팀 |

확정된 날까지 자료가 오지 않으면, 그 자료에 기대는 분석·개발 일정이 밀려요.

## 7. 일정이 바뀌는 경우

| 생기는 일 | 영향 |
|---|---|
| 1~2주차 자료 일정·담당자 확정이 늦어짐 | 분석·개발 일정 확정 지연 |
| 확정된 날까지 자료가 안 옴 | 그 자료에 기대는 개발 순연 |
| 현지 Invoice 양식 추가 | 판독 개발 기간 증가 |
| 개발 중 항목 추가 | 설계·개발 기간 증가 |
| 계산 방식 추가 | 산출 로직 재설계 |
| 기존 데이터 오류가 많음 | 정제·이관 기간 증가 |
| 이관 중 예외처리 추가 | 이관 기간 증가 |
| 사용자 검증 수정사항이 많음 | 보완 기간 증가 |
| 사용자 검증이 늦어짐 | 운영 적용도 지연 |

전제: 범위 유지, 1~2주차에 선행자료·담당자 확정, 일정대로 자료 제공, Invoice 양식·산출 기준이 크게 바뀌지 않음, 이관 범위 1~2주차 확정, 중간·최종 검증에 물류팀 참여.
