# 요구사항 정리

매뉴얼 이후 확인한 내용이에요. 정해지는 대로 이 문서를 고쳐요.

## 확정

- **범위**: [`scope-schedule.md`](scope-schedule.md)가 기준이에요. 매뉴얼의 입고·출고·배차·재고 보고서는 예시이고, 배차는 만들지 않아요.
- **보고 흐름**: 지금은 엑셀 파일을 전달하는 것으로 끝나요. 앱 안에서 결재하는 흐름은 없어요.
- **로그인 필요**. 역할은 둘이에요.
  - 보고자: 보고서와 기본 데이터를 쓰고 고칠 수 있어요
  - 열람자: 내려받기만 할 수 있어요
- **재고**: 지금은 인보이스 엑셀 파일의 입고·출고 값을 엑셀 함수로 더하고 빼서 구해요. 앱에서도 입고·출고 기록으로 계산하는 방식이 기준이에요.
- **서버**: 사내에 둬요. 원하는 기술 스택은 따로 없어요.
- **역할 나눔**: 서버(API·DB)는 서버 담당이 따로 만들어요. 이 저장소는 화면(프런트엔드)만 만들어요.
- **배포**: 서버가 화면까지 같이 내보내요. 화면은 `npm run build` 결과(`dist/`)만 넘기고, 화면과 API가 같은 주소를 써요(API는 `/api` 아래). 파일이 없는 주소(`/auth/callback` 등)는 `index.html`로 돌려줘요. 외부 클라우드(Vercel 등)에는 올리지 않아요. 서버 담당용 안내는 [`deploy.md`](deploy.md).
  - 테스트 서버와 운영 서버가 따로 있어요. 지금은 테스트 서버만 떠 있어요. 주소는 서버 담당에게 받아요(공개 저장소라 적지 않아요).
  - develop에 머지되면 빌드해서 테스트 서버에 올리는 자동 배포 워크플로는 서버 담당이 PR로 올려요.
- **로그인**: [`auth.md`](auth.md)의 약속대로 서버가 만들었어요(2026-10-12). 경로는 `/api/auth/...` 아래예요. 서버의 API 명세는 테스트 서버의 `/swagger-ui/`에서 봐요.
- **API 공통 약속**: 날짜 `YYYY-MM-DD`, 금액·단가·환율은 문자열(decimal), 오류는 `{ "message": "..." }`, 401은 다시 로그인·403은 권한 없음, 목록은 기간 필터와 페이지 나누기.
  - **목록 받기·칸 고치기** (2026-10-13 서버 합의, 열과 상관없이 모든 목록에 같게):
    - 받기: `GET /api/<목록>?from=YYYY-MM-DD&to=YYYY-MM-DD&page=0&size=500` → `{ "items": [...], "total": 숫자 }`. `page`는 0부터, `size` 상한은 1000(화면은 500씩 받아요).
    - 고치기: `PATCH /api/<목록>/{id}`에 고친 칸만 `{ "칸": 값 }`으로 보내요(지우면 `null`). 응답은 계산 칸까지 다시 구한 행 전체예요.
    - 목록별 경로와 열 이름·모양은 물류팀 자료가 오면 정해요.
- **목록 화면은 엑셀처럼** (2026-10-12): 기간을 고르면 그 기간 행을 다 받아 한 화면에 길게 보여줘요(페이지 번호 없음).
  - 열마다 필터(엑셀 자동 필터처럼 값 골라 거르기, 같은 메뉴에 정렬)
  - 칸 범위 고르기(끌기·Shift+방향키·Ctrl+A)와 복사(Ctrl+C → 엑셀에 붙여넣기). 고른 숫자 칸의 합계를 위에 보여줘요
  - 표 안에서 바로 고치기 — **직접 입력 칸만, 보고자만.** 자동 칸(판독·계산·마스터)은 막아 둬요(고칠지 미정)
  - 첫 화면은 수출신고취합(`src/results/ExportDeclarationsPage.tsx`), 표는 `src/components/grid/`. 다른 목록도 이 틀을 써요

## 매뉴얼의 예시 값

매뉴얼에 나온 품목(A-100 등), 표 열, 문서번호 형식(`OUT-20261007-01`)은 **이해를 돕기 위한 예시**예요. 실제 항목이 아니에요.
