# 요구사항 정리

매뉴얼 이후 확인한 내용이에요. 정해지는 대로 이 문서를 고쳐요.

## 확정

- **범위**: [`scope-schedule.md`](scope-schedule.md)가 기준이에요. 매뉴얼의 입고·출고·배차·재고 보고서는 예시이고, 배차는 만들지 않아요.
- **보고 흐름**: 지금은 엑셀 파일을 전달하는 것으로 끝나요. 앱 안에서 결재하는 흐름은 없어요.
- **로그인 필요**. 역할은 둘이에요.
  - 보고자: 보고서와 기본 데이터를 쓰고 고칠 수 있어요
  - 열람자: 내려받기만 할 수 있어요
- **재고**: 지금은 인보이스 엑셀 파일의 입고·출고 값을 엑셀 함수로 더하고 빼서 구해요. 앱에서도 입고·출고 기록으로 계산하는 방식이 기준이에요.
- **서버**: 사내에 둬요. 원하는 기술 스택은 따로 없어요.
- **역할 나눔**: 서버(API·DB)는 서버 담당이 따로 만들어요. 이 저장소는 화면(프런트엔드)만 만들어요.

## 매뉴얼의 예시 값

매뉴얼에 나온 품목(A-100 등), 표 열, 문서번호 형식(`OUT-20261007-01`)은 **이해를 돕기 위한 예시**예요. 실제 항목이 아니에요.

## 받을 자료

- [ ] 결과물별 항목과 양식(수출신고취합·현지 Invoice List·수금현황·U71X Offset·재고/선적 관리·재고/출하 현황). 실데이터는 바꿔서 받아요. 그 밖의 선행자료는 [`scope-schedule.md`](scope-schedule.md) 6장
- [ ] Invoice 양식 샘플(한국 5종·현지 6종) — 나중에 보내 주기로 했어요. 받으면 엑셀인지 PDF인지 보고 판독 방식을 정해요
- [ ] 엑셀 샘플(지금 쓰는 보고서 파일)
- [x] 범위와 일정 → [`scope-schedule.md`](scope-schedule.md) (15주, 착수일 미정)

## 미정

- 서버와 맞출 것: API 주소·명세(OpenAPI 등), 엑셀·PDF를 서버가 만드는지 화면이 만드는지
- 로그인: DVI 통합 로그인을 Hi_yo와 같은 방식으로 붙여요. 서버와 맞출 경로는 [`auth.md`](auth.md)에 있고, 서버 쪽은 아직 없어요

- 단가가 바뀌었을 때 이미 쓴 보고서 금액을 어떻게 할지, 자동 값을 손으로 고칠 수 있는지
- 문서번호 규칙
- 출력물에 결재란(도장 칸)을 넣을지
